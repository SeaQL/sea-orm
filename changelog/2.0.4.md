# SeaORM 2.0.4

*(since 2.0.3)*

## Enhancements

* Add `select_except` to select every column of an entity except the given ones https://github.com/SeaQL/sea-orm/pull/3211

  Rows still hydrate into the full `Model`, so only `Option<_>` columns can be excluded. It replaces any prior selection, so it does not compose with `select_only` / `column`.

  ```rust
  // `body: Option<String>` is left out of the query and comes back as `None`
  let posts = post::Entity::find()
      .select_except([post::Column::Body])
      .all(db)
      .await?;
  ```

* Make `sea-orm-migration` depend only on the SeaORM features it needs https://github.com/SeaQL/sea-orm/pull/3200

  `sea-orm-migration` previously enabled all of SeaORM's default features. Any project using it therefore compiled SeaORM with `stream` and its `aliasable` dependency, even if it disabled them.

  It now enables only `schema-sync` and `macros`, so the features you set on `sea-orm` are the ones you get. See the compatibility note below.

  ```toml
  sea-orm = { version = "2.0.4", default-features = false, features = ["macros", "sqlx-postgres"] }
  sea-orm-migration = "2.0.4" # no longer turns `stream` and the other defaults back on
  ```

## Bug Fixes

* Fix chained `left_join_linked` joining multi-hop links onto the wrong alias https://github.com/SeaQL/sea-orm/pull/3199

  When `left_join_linked` was called more than once, each hop after the first in a later call joined onto the aliases of the first call. The query ran without an error but returned incorrect rows.

  ```rust
  cake::Entity::find()
      .left_join_linked(CakeToFilling)
      .left_join_linked(CakeToFillingVendor)
  ```

  ```sql
  -- before: r3 joins through the first link's r0
  LEFT JOIN `filling` AS `r3` ON `r0`.`filling_id` = `r3`.`id`

  -- after
  LEFT JOIN `filling` AS `r3` ON `r2`.`filling_id` = `r3`.`id`
  ```

* Respect `condition_type` in linked joins https://github.com/SeaQL/sea-orm/pull/3203

  `left_join_linked` and `find_linked` always combined a hop's `on_condition` with the join condition using `AND`, even when the hop set `ConditionType::Any`. This contradicted the documented behavior of `condition_type`, which plain `join()` already followed.

  The two conditions are now combined according to `condition_type`.

  ```rust
  cake::Relation::Fruit
      .def()
      .condition_type(ConditionType::Any)
      .on_condition(|_left, right| {
          Expr::col((right, fruit::Column::Name))
              .like("%tropical%")
              .into_condition()
      })
  ```

  ```sql
  -- before
  LEFT JOIN `fruit` AS `r0` ON `cake`.`id` = `r0`.`cake_id` AND `r0`.`name` LIKE '%tropical%'

  -- after
  LEFT JOIN `fruit` AS `r0` ON `cake`.`id` = `r0`.`cake_id` OR `r0`.`name` LIKE '%tropical%'
  ```

* Apply the `save_as` cast to the array in `eq_any` / `ne_all` https://github.com/SeaQL/sea-orm/pull/3208

  The array operand was sent uncast, so on a `citext` column the comparison ran against `text[]` and was case-sensitive. The array is now cast to the matching array type through the new `ColumnTrait::save_array_as`, which is a no-op by default.

  ```rust
  #[sea_orm(column_type = r#"custom("citext")"#, save_as = "citext")]
  pub email: String,

  Entity::find().filter(Column::Email.eq_any(["a@x.com".to_owned(), "B@x.com".to_owned()]))
  ```

  ```sql
  -- before: text[], case-sensitive
  WHERE "user"."email" = ANY(ARRAY ['a@x.com','B@x.com'])

  -- after
  WHERE "user"."email" = ANY(CAST(ARRAY ['a@x.com','B@x.com'] AS citext[]))
  ```

* Fix schema sync failing to drop a stale unique index on MySQL https://github.com/SeaQL/sea-orm/pull/3202

  Removing `#[sea_orm(unique)]` from a column made the next sync send `DROP INDEX` without its table, which MySQL rejects with error 1064. PostgreSQL and SQLite were unaffected.

  ```sql
  -- before
  DROP INDEX `ref_no` ON

  -- after
  DROP INDEX `ref_no` ON `sync_order`
  ```

## Compatibility Notes

* `sea-orm-migration` no longer enables SeaORM's default features (#3200).

  A project that sets `default-features = false` on `sea-orm` and relied on `sea-orm-migration` to turn them back on must now list them itself: `with-json`, `with-chrono`, `with-time`, `with-uuid`, `with-rust_decimal` and `stream`. A missing one shows up as a compile error, except `sqlite-use-returning-for-3_35`, which only changes how inserted rows are read back on SQLite.

  Projects using `sea-orm` with its default features are unaffected.

  ```toml
  sea-orm = { version = "2.0.4", default-features = false, features = [
      "macros",
      "with-chrono",
      "with-json", # list the features you actually use
  ] }
  ```

* #3203 changes query results for links that set `ConditionType::Any`: they now return the rows the condition describes. Links that do not set `condition_type` are unaffected.

* #3208 changes the generated SQL for `eq_any` / `ne_all` on columns with `save_as`.

  Assertions on the generated SQL need to be updated.
